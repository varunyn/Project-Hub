# Product

## Register

product

## Users

The primary user is the owner of this local development machine: a developer managing many personal and experimental projects across local folders. They use Project Hub while actively deciding what to resume, inspect, maintain, update, or clean up.

## Product Purpose

Project Hub is a local-first dashboard for cataloging development projects. It keeps project metadata, paths, quick launch actions, notes, goals, tags, tech stacks, recent git activity, and dependency update reports in one focused app. Success means the user can quickly understand project status, jump back into work, and spot maintenance issues without opening multiple folders or tools.

## Brand Personality

Focused, practical, trustworthy.

The product should feel like a dependable personal operations console for development work: calm enough for repeated daily use, dense enough to avoid wasting space, and direct enough that every control clearly maps to a real local workflow.

## Anti-references

Avoid flashy AI-dashboard styling, decorative marketing-page drama, oversized hero layouts, vague productivity copy, and interfaces that bury local developer actions behind ornamental UI. Avoid turning practical maintenance data into long, page-dominating lists when summaries and drill-downs would work better.

## Design Principles

1. Keep the current quest visible. Important maintenance or metadata surfaces should summarize first and preserve access to the rest of the dashboard.
2. Optimize for resuming work. Navigation, search, recent activity, quick actions, and status cues should help the user decide what to open next.
3. Prefer local truth over polish theater. Paths, commands, git activity, report timestamps, warnings, and dependency states should be concrete and inspectable.
4. Use density with hierarchy. The app should fit meaningful information above the fold without becoming visually noisy.
5. Make actions explicit. Running reports, opening editors, copying paths, scanning projects, editing metadata, and viewing full details should be obvious and reversible when possible.

## Accessibility & Inclusion

This is a personal local tool, so formal accessibility compliance is not a product requirement. Still preserve readable contrast, keyboard-visible focus states, stable layouts, and reduced-motion-friendly behavior as baseline engineering quality.
